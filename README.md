# table

[![ci](https://github.com/alpibrusl/lexsys-table/actions/workflows/ci.yml/badge.svg)](https://github.com/alpibrusl/lexsys-table/actions/workflows/ci.yml)

**Select, filter, group and aggregate CSV and TSV, for agents and scripts.** One small binary that reads a file in one bounded pass and answers with a document: bounded memory, exact integer arithmetic, byte-stable output, every refusal a named rule with a repair, and an authority report the compiler derived and CI checks. Written in [lex-sys](https://github.com/alpibrusl/lex-sys), one of the [lexsys-tools](https://github.com/alpibrusl/lexsys-tools) family. The [project page](https://alpibrusl.github.io/lexsys-table/) has the pictures.

**Status: early, one reader and one plan, and not pandas.** What is built: the shape, `--select`, `--where`, `--group` with `count`, `sum`, `min`, `max` and `distinct`, `--sort` and `--top` of the groups, `--threads`. What is not: no row sort yet (a branch for it is in progress), no JSON lines, no joins, no `--query`, no stdin, no `mean`, no decimals, no type inference. It is not pandas, and not DuckDB: it answers a small set of questions exactly, and refuses the rest. Where it loses to other tools, and by how much, is on the [evidence page](https://alpibrusl.github.io/lexsys-table/evidence.html) and in [docs/adversarial.md](docs/adversarial.md). The whole list: [docs/backlog.md](docs/backlog.md).

## What you get

* **Bounded memory.** The file is read in 64 KiB chunks; memory is the longest record, the header and a page of output, not the file. About 2 MB on a 31 MB file, and flat on a 1 GB one ([docs/adversarial.md](docs/adversarial.md)).
* **Exact arithmetic.** `bytes:int > 50000` compares 64-bit integers; a sum past 64 bits is `agg.sum-overflow`, never a wrap. A cell that is not an integer, an empty one included, is a refusal that names its row, line and column, never a coercion or a float.
* **A real CSV reader.** RFC 4180: quoted fields, doubled quotes, delimiters and newlines inside quotes, CRLF, a byte order mark. Checked against Python's `csv` module.
* **Byte-stable.** The same file and plan give the same bytes; groups come out in key order. `--threads N` gives the sequential answer byte for byte, the same refusal included.
* **Every refusal is a rule.** A named rule tag for each, with an exit code and, where one exists, a `repair` an agent can follow. An unknown column names the header; `Status` for `status` comes with the corrected command.
* **Self-describing.** `table introspect` prints the flags, rules, limits and schema; `table skill` prints a usage note. Both are generated from the tables the parser runs on.
* **A checkable authority.** No network, no foreign code, no clock, nothing written to disk: the compiler derived it, [`manifests/table.authority.json`](manifests/table.authority.json) records it, and CI fails if the binary says otherwise.

## Quick start

You need `git`, Rust, `clang` and `python3`. The compiler is the commit `lex-sys.toml` pins:

```sh
git clone https://github.com/alpibrusl/lex-sys                           # the compiler
git clone https://github.com/alpibrusl/lexsys-table && cd lexsys-table
REV=$(sed -n 's/^lex-sys *= *"\([0-9a-f]*\)".*/\1/p' lex-sys.toml)        # the compiler these sources need
(cd ../lex-sys && git fetch -q origin && git checkout "$REV" && cargo build --release -p lex-sys)
export PATH=$PWD/../lex-sys/target/release:$PWD/build:$PATH
lex-sys build                                                            # installs the contract package, builds build/table
```

A small file, with a quoted comma and an empty cell:

```sh
cat > orders.csv <<'EOF'
id,customer,status,bytes
1,"Doe, Jane",200,512
2,Acme,404,
3,"Doe, Jane",200,2048
4,Acme,500,128
5,Zed,200,64
EOF
```

What `table` answers (the output below is generated by `scripts/site.py` from the built binary, and CI checks it has not drifted):

<!-- gen:readme-demo -->
```console
$ table orders.csv
{"ok":true,"command":"table","schema":"table.v2","data":{"headers":["id","customer","status","bytes"],"column_count":4,"row_count":5,"truncated":false},"meta":{"version":"0.3.0"}}
$ table --select customer,bytes --format csv orders.csv
customer,bytes
"Doe, Jane",512
Acme,
"Doe, Jane",2048
Acme,128
Zed,64
$ table --where "bytes != '' and bytes:int > 100" --select id,customer --format csv orders.csv
id,customer
1,"Doe, Jane"
3,"Doe, Jane"
4,Acme
$ table --where "bytes != ''" --group customer --agg count,sum:bytes --sort -sum:bytes --format csv orders.csv
customer,count,sum:bytes
"Doe, Jane",2,2560
Acme,1,128
Zed,1,64
$ table --where 'bytes:int>100' --select id --format csv orders.csv
table: value.not-integer: a cell is not an exact integer: an optional sign and digits, nothing else (an empty cell is not one)
id
1
# exit status 8
```
<!-- /gen:readme-demo -->

The last command is the point: the empty cell is not an integer, so the answer is a refusal, not a guess; the row before it, written already, stands, and the exit code says the output is a prefix. Add `--where "bytes != ''"` to say which rows you mean (conditions stop at the first false one). Without `--format csv` the same refusal is one JSON line with `rule`, `hint`, `repair` and `detail`: row 2, line 3, column `bytes`.

## Contributing

Every change goes through what CI runs: `lex-sys fmt --check tools generated`, `lex-sys build`, `scripts/schemas.py --check`, `scripts/manifest.py --check`, the conformance tests, and `scripts/site.py --check`. Design before code, in `docs/`; the gates are fixed before the build; each new piece gets mutants (`scripts/*_mutants.py`, not run in CI) and each claim is measured, with the conditions next to the number. A claim that turns out false is corrected in place. After a change to the program, `python3 scripts/site.py` rewrites the generated parts of this file and of the pages.
