# Reader options for dirty exports: `--skip-lines`, `--skip-prefix`, `--na`, `--decimal`, `--thousands` (issue #109): a design

> **Status: accepted by the maintainer on 2026-11-10 (section 7, decisions 1 to 6, all as proposed); building follows with O1 (section 8).** Written 2026-11-10 for cancho-table#109, slice 2 of #101; #111 (decided 2026-11-09, `docs/backlog.md` item 14) says `table` takes **read-time rules only**, and these are those. It follows the rules of `docs/numbers.md`: what is measured is said as measured (here only counts of places in the code, by grep), the rest is a reading of the code or a judgement, and what only a person can decide is in section 7. Nothing here is a claim about speed: **every cost below is unmeasured**, and the gate for each slice is that the reader's cost without the options is the cost of `main` (section 6).

## 1. What the options are

All of them say how a CSV file is *read*, as `--delimiter` does; none rewrites a value.

| flag | reads | example |
|---|---|---|
| `--skip-lines N` | drops the first N physical lines, before the header | an export with a title block |
| `--skip-prefix P` | drops the lines before the header that start with P | `# generated by ...` |
| `--na 'A,B'` | a cell that is exactly one of the markers is read as the empty cell | `?`, `NA`, `n/a` |
| `--decimal C` | the character that separates the fraction in a typed number | `,` |
| `--thousands C` | the character that groups the integer part | `.` |

`--skip-suffix-rows N` (a trailer) is in the issue and is a decision (section 7, 1): it is the one that does not fit a stream.

## 2. Where each one acts: counts, by grep, on `main` at `793097a`

* **The preamble** acts before the header. The header is found in `table.cho` (the file loop and its copy for standard input, `scripts/stream.py`), `scan.cho`/`par.cho` (a range of a parallel read starts after the header: it needs the offset where the data begins), `jnhead.cho` (the header of a join's files), `explain.cho` (the first 64 KiB), `jdisc.cho` is JSON lines and is out. `reader.split_header` is called from four files, `lines.start` from eight. **No row-by-row cost**: the preamble is read once.
* **`--na`** acts on a cell. A cell is looked at by the conditions, the groups, the aggregates, the order keys, the join keys, the report, and written by the selection; the places that turn a cell into a value are `cellnum`, `dec` and `flt` (called from five files: `agg`, `expr`, `query`, `report`, `sorter`) and the comparisons of `expr`. There is no one function that every read of a cell goes through, and the hot loop does not call one for an untyped cell. This is the expensive one, and the one with a decision (section 7, 3).
* **`--decimal` and `--thousands`** act where a typed cell becomes a number: `cellnum.parse_int`, `parse_dec` and `dec`/`flt` (143, 311 and 466 lines). A pre-pass that rewrites the cell into the form they already read (`35.741,59` into `35741.59`) costs nothing for a call without the options, if it is a separate path that the option selects; it costs a copy of the cell for a call with them, only for the typed cells.

## 3. The rules, to settle once

**Skipping.** `--skip-lines N` counts physical lines of the file, quoted newlines or not: a preamble is text, and a quote in it must not open a record. `--skip-prefix P` drops, before the header, the lines that start with P (more than one: each is looked at until the first that does not); **after** the header a line that starts with P is a row. The count is reported: `data.skipped` ( `{"lines":N}`, present only when an option was given) in the answer, and in `--explain`; rows are never dropped silently. An option that would skip the whole file leaves an empty file, which is answered as an empty file is (**corrected in the build, section 9**: the design said it would be refused with a rule of its own).

**`--na`.** The markers are compared byte for byte (not trimmed, not case-folded), a list with the escapes of `--select`. A cell that is a marker is the empty cell **everywhere it is read**: so `--where 'x = '''` keeps it, a typed column refuses it exactly as it refuses an empty cell (`value.not-integer` and the repair of #107: the guard `x != ''` in front), a group key is the empty key, a join key is the empty key, and (section 7, 3) it is written empty. It is not counted in the answer: the cells a call read are the call's, and a count of the markers it replaced would be a count of cells the plan happened to look at.

**Number syntax.** Only for `:dec(S)` and `:float` (and not `:int`, `:date`, `:timestamp`): `--decimal` alone says the fraction separator, and a cell with a group separator is refused; `--thousands` alone is refused as `args.required-flag` (it needs to know the decimal). With both, the integer part is groups of three digits separated by the thousands character, the first group 1 to 3 digits (`35.741,59` is 35741.59; `1.234` is 1234, a group, not a decimal; `12.34` is refused; `1,234.5` with `--decimal ,` is refused). The two characters must differ, be one byte each, and not be a digit, a sign, an exponent letter or the delimiter. A cell that fits neither the plain syntax nor the stated one is the refusal it is today (`value.not-decimal`, `value.not-float`) with `detail.syntax` saying which was in force; the repair is `none`, with a reason that says what the cell would have to be. The plain syntax is **not** accepted beside the stated one (`35741.59` with `--decimal ,` is refused): two spellings of a number in one column is the ambiguity the issue asks to refuse.

**The `--join` file.** The options apply to FILE and to the `--join` file alike, as `--input-format` and `--delimiter` do ("the `--join` file is read as FILE is unless it is told otherwise"); a `--join-skip-lines` and the others are a later slice, if anyone needs a file with a preamble joined with one without. `--query` has no reader options (docs/query.md section 6): they stay flags, and are given with it.

**MCP.** Properties like the others (generated from the flag table), with short texts.

## 4. Slices, in the order proposed

1. **O1, the preamble** (`--skip-lines`, `--skip-prefix`): the offset where the data begins, found once and given to the sequential read, the ranges and the joins' headers; `data.skipped`. No cost without the options by construction.
2. **O2, number syntax** (`--decimal`, `--thousands`): the pre-pass in the typed readers; the refusals.
3. **O3, `--na`**: the cell reads. The slice that can cost, and the one to measure first (section 6) before it is built.
4. **O4, the trailer**, if section 7, 1 says yes.

## 5. Not decided here, because it follows the decisions

The rule tags (a new `parse.csv-no-header`, or the existing ones with a detail), the text of the hints, the names in `data.skipped`, and the repair of the cell that fits the other syntax (a `choose` between the call with and without the option is possible when the cell parses the other way).

## 6. The gates, written before the code

* **Without the options, `main`.** The benchmarks of the reader (`scripts/cellcost.py`, `bench_matrix.py`, the named benchmarks) give `main`'s numbers within noise, and the corpus md5 of the equivalence gates is unchanged. For O3 this is a number to find before the slice is accepted: if `--na` costs a call without it, the slice does not go in as designed.
* **The oracle.** A corpus of exports with a preamble, markers and both number syntaxes, read two ways: the options on the dirty file, and a file cleaned by a Python script that shares no code with the tool, on the plain flags. Equal answers, for rows, groups, sorts, joins and the report, with threads and without.
* **The refusals.** Each ambiguity above has a fixture and a rule; the number reader's mutants (the sign, a group of the wrong width, two decimal separators, the thousands character in the fraction); no input reaches a panic.
* **The skipped lines are counted**, and the count is the number of lines the options removed, on a file with a quote in the preamble.

## 7. What is not decided, and is a person's

1. **The trailer** (`--skip-suffix-rows N`). A stream cannot know which rows are the last N without holding them: a window of N records (bounded by `--max-line-bytes` times N, a new bound), and a parallel read would need the last range to know the end. Proposed: **not built**; a trailer is removed with `--where` on a column the export marks it with, and an export that marks nothing is a job for the cleaning tool of #111.
2. **`--skip-prefix` scope.** Before the header only (proposed: a row that starts with `#` is data, and a per-row check costs), or any line.
3. **`--na` and the output.** The marker is the empty cell *everywhere*, including in what is written (proposed: it makes `--out` the glue of the cleaning pipeline, and keeps one meaning of "empty"), or only for the typing and the comparisons while the output keeps the cell as it was read (cheaper: the selection copies bytes).
4. **The `--join` file.** The options apply to both files (proposed, the precedent of the reader flags), or to FILE only with the `--join` file read as before, or a `--join-` family in the same slice.
5. **The rule for a bad number.** The existing `value.not-decimal` and `value.not-float` with a `detail.syntax` (proposed: no new tag for a case that is the same refusal), or a new `value.number-syntax`.
6. **The order**: O1, O2, then O3 after its measure (proposed), or O3 first because the markers are what the evidence of #101 mostly shows.

**Not measured:** every cost above, and whether the five options are the ones that dirty exports need (the evidence in #101 is three runs of one model on one task: it shows where agents leave the tool, not that all of the list belongs in `table`).

## 8. Decided, 2026-11-10

The maintainer answered "yes to all six, as proposed": (1) **no trailer** (`--skip-suffix-rows` is not built; a trailer is removed with `--where`, or by the cleaning tool of #111); (2) `--skip-prefix` acts **before the header only**; (3) `--na` reads a marker as the empty cell **everywhere, in the output too**; (4) the options apply to **FILE and the `--join` file alike**, with no `--join-` family yet; (5) a bad number is the existing **`value.not-decimal` / `value.not-float` with a `detail.syntax`**, no new tag; (6) the order is **O1, O2, then O3 after its cost is measured**. O4 (the trailer) is therefore dropped. O1 is next.

## 9. O1 as built (2026-11-10), and where the build differs from the design

* **Where it acts.** `--skip-lines N` and `--skip-prefix P` are in the flag table (`skip-lines` a number, `skip-prefix` a text, MCP properties like the others). The sequential read (`table.cho`, and `read_stream` made from it), the header of a join (`jnhead.head_of`, for FILE and for the `--join` file) and the header of `--explain` (`explain.read_head`) drop the lines; the parallel read and the partitioned joins start after the header the sequential read found, so they need nothing (a parallel read, and standard input, are tested against the clean file). **No cost for a data line**: the new branch of the read loop sits after the data branch in the chain, so a data row never evaluates it; the only changed condition is the one of a blank line (`number >= skip_n`, evaluated only for a blank line). *Measured afterwards* (this container, 4 CPUs, one 67 MB file of 3,000,000 rows, `--threads 1`, best of 5, against the binary built before `--out` was merged, so the differences are those of all the work since and not of O1 alone): `--select id,name --where 'v:int > 500000' --format csv` 0.254 s before and 0.261 s after (+2.7%), `--group name --agg count,sum:v:int` 0.311 s and 0.267 s (-14%), `--order-by -v:int --top 1000` 0.150 s and 0.149 s (-0.7%): within the noise of this machine, which is not the maintainer's. The benchmark scripts (`cellcost.py`, `bench_matrix.py`) were not run for it. This goes in before `--na`, which is the slice that can cost.
* **The count.** `data.skipped.lines` in the json answer of the shape, rows, groups and the report, present only when an option was given (zero is said), and `data.skipped.join_lines` for the `--join` file of a join. csv and JSON lines have no document and say nothing; `--explain` shows the options (`source.skip_lines`, `source.skip_prefix`) and **not the count**, since it reads the header and nothing after (the design said both). The schema (`schemas/table.v2.json`) has `skipped` and the two `source` keys as optional.
* **Physical lines.** The lines of an error and of the report (`first_empty_line` and the others) are the file's, preamble included: a preamble of three lines moves every line number by three, and the rows (`first_empty_row`) are the rows of the table. The test says so.
* **JSON lines** refuse the options (`args.conflict`), also when the `--join` file is JSON lines, since there is no preamble to drop.
* **A header that spans lines** is not cut by a prefix: a line that starts with the prefix inside a quoted header is the header's.
* **Equal to the clean file.** `tests/conformance/test_preamble.py` reads a dirty file with the options and the same table without the preamble, for the shape, rows, groups, sorted rows, the report, csv and JSON lines out, standard input, 1 and 4 threads, and the four join types, and compares; `scripts/preamble_mutants.py` has the mutants (32; `--check` in CI): 31 were killed by the first tests and one, the blank line among the first N of a join file's header, needed a test of its own.
* **Both files alike has a price, as decided.** A join of a file that has a title block with one that has none cannot use `--skip-lines` (it would drop the second file's header): the `--join-skip-lines` family of decision 4 is the way out, and is not built.

## 10. O2, number syntax: what the code says (2026-11-10), and a decision

Section 2 said the pre-pass for `--decimal`/`--thousands` "costs nothing for a call without the options, if it is a separate path that the option selects". Reading the call sites says it is not that simple, and the maintainer should choose between two ways before O2 is built.

**What was counted** (by reading, not measured). A typed cell becomes a number at 16 places: `expr.cho` (nine: the conditions of `--where`, the keys of the order, the membership test), `query.parse_typed` (three: the aggregates), `report.classify` (three), `agg.add_fast` and `sorter.key_value` (one each). **Fifteen of the sixteen are in functions that do not receive the plan** (`query.Query`): they are given the cell's bytes and the type, nothing else. The separators would have to reach them through the evaluators that call them (`expr`, `agg`, `sorter`, `report`), which means a parameter added to every function on the way from the row loop down; the number of those functions is not counted, and it is the cost of way A.

**A. Thread the syntax down** (the design as written): the two separator bytes travel with the plan to each of the sixteen places, and a cell with the option set is rewritten into the plain form in a small buffer there. The original text of a cell is what `--select` and the output show, as always. Cost: many signatures, each in a loop that is held to `main`'s numbers; benefit: the output is untouched.

**B. Repoint the cell at the row boundary**: after the fields of a row are split and before the row is handed to the filter, the aggregates and the sorter, the typed `:dec`/`:float` columns of the plan are rewritten into a scratch region and their (first, last) pair repointed there, as the join already repoints a probe cell (`jnread.build_only`). Nothing below the boundary changes: the sixteen places see plain numbers. Cost: one branch per row, taken only with the option set, in the function that all forms share (`engine.process_rows`), and a scratch region. **Consequence the maintainer decides:** a column that the plan reads as `:dec(S)` or `:float` (in `--where`, `--agg`, `--order-by`) and that `--select` also shows would be shown in the plain form (`35741.59`), and a column the plan does not type would be shown as it was (`35.741,59`). That is a value rewritten in the output, which #111 put outside `table`; it is also what makes `--out` the glue of a pipeline that reads a European export and writes a plain one.

**Proposed:** B, with the output rule stated as above, because it changes one function and not the sixteen; and because the other half of the cleaning (`--na`, decision 3) already writes the read form of a cell. If the maintainer prefers that the output keep the original text, A is the way and O2 is a larger slice than the others; if neither is wanted, O2 is dropped and `35.741,59` stays a job for the cleaning tool.

**Decision 7 (new):** A (the output keeps the cell as it was), B (the output shows the plain form of a typed column), or drop O2. Nothing of O2 is built until it is answered.

### 10.1 Decision 7: B chosen, and a correction of what B costs (2026-11-10)

The maintainer answered "B, as proposed". Before building it the call sites were counted, and the claim on which B was proposed ("it changes one function": `engine.process_rows`) is **false**. A row is split into its cells by `reader.fields`, and the loops that call it are not one: **6 in the sequential and the parallel CSV read** (`table.cho`: two, and two more in its copy for standard input; `scan.cho`: two, for the ranges of a parallel read), **2 in the sorted and merged runs** (`psort.cho`, `finish.cho`), and **19 in the joins** (`jnread` 7, `jn3pass` 6, `jnmerge` 2, `jnjson` 2, `jnprange` 1, `jnswap` 1, probe and build, in single-line and multi-line forms), counted by grep of `reader.fields(`. `process_rows` is called only after the split by the sequential loops, and the parallel loops, the group fast paths (`group_plain`) and the joins reach the cells without it. B therefore needs a hook after the split at each of those sites, which rewrites the typed cells of the row into a scratch buffer and repoints the row at it, not one branch in one function.

What B needs, counted: (1) the hook itself (a function that, given the row, its cells, the columns the plan types as `:dec` or `:float` and the two separators, writes the row with those cells in the plain form and answers the new row and cells; written once, tested alone, with the number reader's mutants); (2) the typed columns of the plan, resolved to positions (the plan holds them by kind, in conditions, aggregates and order keys; `frame.prepare` resolves names, and there is no list of the typed positions yet); (3) the call at each site, in loops held to `main`'s numbers, with a borrow of the scratch buffer where the row is used, so that the code that follows reads the new row; (4) the same hook for `--na` (O3), which has the same shape and would share (1) to (3).

**So O2 and O3 are one piece of work, the row normalizer, and a larger one than section 4 said.** Proposed, for the maintainer to confirm or change (nothing is built until then):

* **Build it once for the sequential and parallel CSV read of FILE** (the 6 sites, and the 2 of sorting): O2 and O3 together, with `--decimal`, `--thousands` and `--na` **refused with `--join`** (`args.conflict`, with a hint that names the cleaning pipeline: write the file with `--out`, then join) until the joins are covered. This **departs from decision 4** (the options apply to both files) for these three options only; O1's `--skip-lines` and `--skip-prefix` stay as built.
* The joins (19 sites) as a later slice, if anyone needs them.
* Or drop O2 and O3: `35.741,59` and the markers stay a job for the cleaning tool of #111, and `--skip-lines` and `--skip-prefix` (built) are what `table` takes from #109.

**Decision 8 (new):** build the row normalizer for FILE only (proposed), build it for FILE and the joins in one slice, or drop O2 and O3.

## 11. O1 corrected, and O2 and O3 as built (2026-11-10)

### 11.1 A correction of section 9: O1 cost the plain read 1.3 to 2.3 percent

Section 9 said O1 added nothing to a call without the options. **That was not measured, and it is false.** Under `valgrind --tool=callgrind` (`perf` is absent here) on 100,000 rows, one thread, the merged O1 retired **+1.3 to +2.3 percent instructions** (17 to 24 a row) against the build before it, over the bound of 1.01 that gate G6 holds the read loop to (`scripts/gate_regress.py --counter`). The test that was written for it (`test_preamble`) measures no instructions, so it passed.

The fix is not a cheaper `if`. Any `if` in the loop costs 9 to 37 instructions a row, so **the options are not in the loop**: `read_file` and `read_stream` are what they were before O1, and a call that gives `--skip-lines`, `--skip-prefix`, `--na`, `--decimal` or `--thousands` runs `read_file_opt` or `read_stream_opt`, which `scripts/readopt.py` makes from them (a list of (needle, replacement) edits that must each match once; `--check` is run by CI, as `stream.py --check` is). `read_any` chooses by the plan. Measured the same way, the plain path is **+0.001 to +0.002 percent** against the build before O1 (the dispatch only), inside the bound.

What an option costs, in instructions of the whole run on 100,000 rows, one thread, against the plain run of the same query: `--skip-prefix` +1.3 to +1.5, `--decimal` / `--thousands` +8.0 to +8.6, `--na` +18.7 to +20.0 percent (each cell is compared with every marker). They are paid by the calls that ask.

### 11.2 O2 and O3 as built: the row normalizer (`numrow.cho`)

Decision 8 was answered "FILE only, as proposed": the normalizer is built for the CSV read of FILE, from a file or standard input, and **`--decimal`, `--thousands` and `--na` are refused with `--join` and with JSON lines** (`args.conflict`; the hint is to write the file with `--out` and read that). `--thousands` without `--decimal` is `args.required-flag`; a byte that is a digit, a sign, e, E, a quote, a line feed, or the same for both is refused as a bad value; the delimiter is allowed as a decimal byte (the cell is then quoted in the file).

* **Where.** After `reader.fields` split the row and before anything reads it, in the option loops (`apply`, called from the four places that call `engine.process_rows` and its group fast paths). Everything below it sees one thing. A row that the options change is **rebuilt as a whole record** (delimiters and quotes kept, the changed cells in their new form) and its cells repointed into it; a row that they do not change is the record as it was. The rebuild is not optional: the sorter keeps the record text and splits it again for the answer, so a row repointed in place and not rebuilt was sorted by the new cells and shown as the old (found by the oracle test, not by reading).
* **`--na`.** A cell that is, byte for byte, one of the markers (a quoted one by the text inside its quotes, except one that holds a quote) is the empty cell: for `--where`, a group key, an aggregate, a sort key, and also in the output (section 8). A typed column refuses it as it refuses the empty cell.
* **`--decimal` / `--thousands`.** Only a cell of a column that the plan reads as `:dec(S)` or `:float` is rewritten, into the plain form (`1.234,5` is `1234.5`); the cells of other columns are shown as they were (decision 7, B). Grammar: an optional sign; the integer part, either ungrouped digits or a first group of one to three digits and then groups of exactly three, split by the thousands byte; the decimal byte and the fraction; an exponent from the first e or E, copied. A cell that is not in the stated syntax, a plain `12.34` beside `--decimal ,` among them, is **refused**: a byte (0x1F, `numrow.sentinel`) is put at its end so that the plain readers refuse it as `value.not-decimal` / `value.not-float`, and the refusal shows the cell without it and adds `detail.syntax` (`decimal , thousands .`). The ambiguity of `1.234` with `--decimal ,` is therefore never guessed: with `--thousands .` it is 1234, without it it is refused.
* **Reads on one core.** The parallel read (`scan.cho`) is not hooked: a call with `--na`, `--decimal` or `--thousands` runs on one thread whatever `--threads` says, and `--explain` says so (`work.threads.reason`). The sorting runs are covered because the rows are normalized before they are kept. `--report` reads the normalized cells and is unaffected.
* **Tests.** `tests/conformance/test_numrow.py`: the oracle (a file in the other syntax with markers, read with the options, against the file a script cleaned: aggregates, groups, a filter, a sort, rows as csv, a parallel-sized file and `--threads 4`), the rules (a plain point beside a stated comma; the group of `1.23`; `--thousands` alone; `--na` in the output; the refusals with a join and JSON lines; standard input; `--explain`). `scripts/numrow_mutants.py`: 40 mutants of the normalizer and of its hooks.
* **Not done:** the joins (19 sites, decision 8), and a parallel read.
