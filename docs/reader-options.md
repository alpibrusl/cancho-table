# Reader options for dirty exports: `--skip-lines`, `--skip-prefix`, `--na`, `--decimal`, `--thousands` (issue #109): a design

> **Status: accepted by the maintainer on 2026-11-10 (section 7, decisions 1 to 6, all as proposed); building follows with O1 (section 8).** Written 2026-11-10 for cancho-table#109, slice 2 of #101; #111 (decided 2026-11-09, `docs/backlog.md` item 14) says `table` takes **read-time rules only**, and these are those. It follows the rules of `docs/numbers.md`: what is measured is said as measured (here only counts of places in the code, by grep), the rest is a reading of the code or a judgement, and what only a person can decide is in section 7. Nothing here is a claim about speed: **every cost below is unmeasured**, and the gate for each slice is that the reader's cost without the options is the cost of `main` (section 6).

## 1. What the options are

All of them say how a CSV file is *read*, as `--delimiter` does; none rewrites a value.

| flag | reads | example |
|---|---|---|
| `--skip-lines N` | drops the first N physical lines, before the header | an export with a title block |
| `--skip-prefix P` | drops the lines before the header that start with P | `# generated by ...` |
| `--na 'A,B'` | a cell that is exactly one of the markers is read as the empty cell | `?`, `NA`, `n/a` |
| `--decimal C` | the character that separates the fraction in a typed number | `,` |
| `--thousands C` | the character that groups the integer part | `.` |

`--skip-suffix-rows N` (a trailer) is in the issue and is a decision (section 7, 1): it is the one that does not fit a stream.

## 2. Where each one acts: counts, by grep, on `main` at `793097a`

* **The preamble** acts before the header. The header is found in `table.cho` (the file loop and its copy for standard input, `scripts/stream.py`), `scan.cho`/`par.cho` (a range of a parallel read starts after the header: it needs the offset where the data begins), `jnhead.cho` (the header of a join's files), `explain.cho` (the first 64 KiB), `jdisc.cho` is JSON lines and is out. `reader.split_header` is called from four files, `lines.start` from eight. **No row-by-row cost**: the preamble is read once.
* **`--na`** acts on a cell. A cell is looked at by the conditions, the groups, the aggregates, the order keys, the join keys, the report, and written by the selection; the places that turn a cell into a value are `cellnum`, `dec` and `flt` (called from five files: `agg`, `expr`, `query`, `report`, `sorter`) and the comparisons of `expr`. There is no one function that every read of a cell goes through, and the hot loop does not call one for an untyped cell. This is the expensive one, and the one with a decision (section 7, 3).
* **`--decimal` and `--thousands`** act where a typed cell becomes a number: `cellnum.parse_int`, `parse_dec` and `dec`/`flt` (143, 311 and 466 lines). A pre-pass that rewrites the cell into the form they already read (`35.741,59` into `35741.59`) costs nothing for a call without the options, if it is a separate path that the option selects; it costs a copy of the cell for a call with them, only for the typed cells.

## 3. The rules, to settle once

**Skipping.** `--skip-lines N` counts physical lines of the file, quoted newlines or not: a preamble is text, and a quote in it must not open a record. `--skip-prefix P` drops, before the header, the lines that start with P (more than one: each is looked at until the first that does not); **after** the header a line that starts with P is a row. The count is reported: `data.skipped` ( `{"lines":N}`, present only when an option was given) in the answer, and in `--explain`; rows are never dropped silently. An option that would skip the whole file is refused, with a rule of its own to be named in the build (a file with no header has none today).

**`--na`.** The markers are compared byte for byte (not trimmed, not case-folded), a list with the escapes of `--select`. A cell that is a marker is the empty cell **everywhere it is read**: so `--where 'x = '''` keeps it, a typed column refuses it exactly as it refuses an empty cell (`value.not-integer` and the repair of #107: the guard `x != ''` in front), a group key is the empty key, a join key is the empty key, and (section 7, 3) it is written empty. It is not counted in the answer: the cells a call read are the call's, and a count of the markers it replaced would be a count of cells the plan happened to look at.

**Number syntax.** Only for `:dec(S)` and `:float` (and not `:int`, `:date`, `:timestamp`): `--decimal` alone says the fraction separator, and a cell with a group separator is refused; `--thousands` alone is refused as `args.required-flag` (it needs to know the decimal). With both, the integer part is groups of three digits separated by the thousands character, the first group 1 to 3 digits (`35.741,59` is 35741.59; `1.234` is 1234, a group, not a decimal; `12.34` is refused; `1,234.5` with `--decimal ,` is refused). The two characters must differ, be one byte each, and not be a digit, a sign, an exponent letter or the delimiter. A cell that fits neither the plain syntax nor the stated one is the refusal it is today (`value.not-decimal`, `value.not-float`) with `detail.syntax` saying which was in force; the repair is `none`, with a reason that says what the cell would have to be. The plain syntax is **not** accepted beside the stated one (`35741.59` with `--decimal ,` is refused): two spellings of a number in one column is the ambiguity the issue asks to refuse.

**The `--join` file.** The options apply to FILE and to the `--join` file alike, as `--input-format` and `--delimiter` do ("the `--join` file is read as FILE is unless it is told otherwise"); a `--join-skip-lines` and the others are a later slice, if anyone needs a file with a preamble joined with one without. `--query` has no reader options (docs/query.md section 6): they stay flags, and are given with it.

**MCP.** Properties like the others (generated from the flag table), with short texts.

## 4. Slices, in the order proposed

1. **O1, the preamble** (`--skip-lines`, `--skip-prefix`): the offset where the data begins, found once and given to the sequential read, the ranges and the joins' headers; `data.skipped`. No cost without the options by construction.
2. **O2, number syntax** (`--decimal`, `--thousands`): the pre-pass in the typed readers; the refusals.
3. **O3, `--na`**: the cell reads. The slice that can cost, and the one to measure first (section 6) before it is built.
4. **O4, the trailer**, if section 7, 1 says yes.

## 5. Not decided here, because it follows the decisions

The rule tags (a new `parse.csv-no-header`, or the existing ones with a detail), the text of the hints, the names in `data.skipped`, and the repair of the cell that fits the other syntax (a `choose` between the call with and without the option is possible when the cell parses the other way).

## 6. The gates, written before the code

* **Without the options, `main`.** The benchmarks of the reader (`scripts/cellcost.py`, `bench_matrix.py`, the named benchmarks) give `main`'s numbers within noise, and the corpus md5 of the equivalence gates is unchanged. For O3 this is a number to find before the slice is accepted: if `--na` costs a call without it, the slice does not go in as designed.
* **The oracle.** A corpus of exports with a preamble, markers and both number syntaxes, read two ways: the options on the dirty file, and a file cleaned by a Python script that shares no code with the tool, on the plain flags. Equal answers, for rows, groups, sorts, joins and the report, with threads and without.
* **The refusals.** Each ambiguity above has a fixture and a rule; the number reader's mutants (the sign, a group of the wrong width, two decimal separators, the thousands character in the fraction); no input reaches a panic.
* **The skipped lines are counted**, and the count is the number of lines the options removed, on a file with a quote in the preamble.

## 7. What is not decided, and is a person's

1. **The trailer** (`--skip-suffix-rows N`). A stream cannot know which rows are the last N without holding them: a window of N records (bounded by `--max-line-bytes` times N, a new bound), and a parallel read would need the last range to know the end. Proposed: **not built**; a trailer is removed with `--where` on a column the export marks it with, and an export that marks nothing is a job for the cleaning tool of #111.
2. **`--skip-prefix` scope.** Before the header only (proposed: a row that starts with `#` is data, and a per-row check costs), or any line.
3. **`--na` and the output.** The marker is the empty cell *everywhere*, including in what is written (proposed: it makes `--out` the glue of the cleaning pipeline, and keeps one meaning of "empty"), or only for the typing and the comparisons while the output keeps the cell as it was read (cheaper: the selection copies bytes).
4. **The `--join` file.** The options apply to both files (proposed, the precedent of the reader flags), or to FILE only with the `--join` file read as before, or a `--join-` family in the same slice.
5. **The rule for a bad number.** The existing `value.not-decimal` and `value.not-float` with a `detail.syntax` (proposed: no new tag for a case that is the same refusal), or a new `value.number-syntax`.
6. **The order**: O1, O2, then O3 after its measure (proposed), or O3 first because the markers are what the evidence of #101 mostly shows.

**Not measured:** every cost above, and whether the five options are the ones that dirty exports need (the evidence in #101 is three runs of one model on one task: it shows where agents leave the tool, not that all of the list belongs in `table`).

## 8. Decided, 2026-11-10

The maintainer answered "yes to all six, as proposed": (1) **no trailer** (`--skip-suffix-rows` is not built; a trailer is removed with `--where`, or by the cleaning tool of #111); (2) `--skip-prefix` acts **before the header only**; (3) `--na` reads a marker as the empty cell **everywhere, in the output too**; (4) the options apply to **FILE and the `--join` file alike**, with no `--join-` family yet; (5) a bad number is the existing **`value.not-decimal` / `value.not-float` with a `detail.syntax`**, no new tag; (6) the order is **O1, O2, then O3 after its cost is measured**. O4 (the trailer) is therefore dropped. O1 is next.
