Ask a CSV a question. Get an exact answer.

A small command-line tool. Pick columns, filter rows, count and sum by a key, in one pass over a CSV or TSV file. Memory stays small however big the file is.

What you can doTry it
$ table --where "bytes != ''" --group customer --agg count,sum:bytes --sort -sum:bytes --format csv orders.csv
customer,count,sum:bytes
"Doe, Jane",2,2560
Acme,1,128
Zed,1,64

What you can do now

Every example below runs on this five-line file, and the output is what the program prints.

id,customer,status,bytes
1,"Doe, Jane",200,512
2,Acme,404,
3,"Doe, Jane",200,2048
4,Acme,500,128
5,Zed,200,64

Pick some columns

Name them; they come out in the order you give. A comma inside a quoted field stays inside it, and the output is quoted again.

$ table --select customer,bytes --format csv orders.csv
customer,bytes
"Doe, Jane",512
Acme,
"Doe, Jane",2048
Acme,128
Zed,64

Keep the rows that match

Text compares byte by byte; :int compares whole numbers exactly. Conditions run left to right and stop at the first false one, so the first one here keeps the empty cell away from the number test.

$ table --where "bytes != '' and bytes:int > 100" --select id,customer --format csv orders.csv
id,customer
1,"Doe, Jane"
3,"Doe, Jane"
4,Acme

Count and sum by a key

count, sum, min, max and distinct, sorted by what you ask for. Sums are exact whole numbers; a sum that would not fit in 64 bits is refused, not wrapped.

$ table --where "bytes != ''" --group customer --agg count,sum:bytes --sort -sum:bytes --format csv orders.csv
customer,count,sum:bytes
"Doe, Jane",2,2560
Acme,1,128
Zed,1,64

Page through the results

JSON answers come in pages. next tells you where the next one starts. Resuming re-reads the file from the start, so paging deep into a huge file gets slow.

$ table --select id,customer --limit 2 orders.csv
{"ok":true,"command":"table","schema":"table.v2","data":{"columns":["id","customer"],"rows":[["1","Doe, Jane"],["2","Acme"]],"row_count":2,"truncated":true,"next":{"from":2}},"meta":{"version":"0.3.0"}}
$ table --select id,customer --limit 2 --from 2 orders.csv
{"ok":true,"command":"table","schema":"table.v2","data":{"columns":["id","customer"],"rows":[["3","Doe, Jane"],["4","Acme"]],"row_count":2,"truncated":true,"next":{"from":4}},"meta":{"version":"0.3.0"}}

Get CSV back

--format csv writes the rows as CSV as they are read, whatever the file size. Every column when you do not pick any. A non-zero exit means the output is only the start of the answer.

$ table --where "status = 200" --format csv orders.csv
id,customer,status,bytes
1,"Doe, Jane",200,512
3,"Doe, Jane",200,2048
5,Zed,200,64

Use several cores

--threads N reads the file with N cores (1 to 64). The answer is the same bytes as with one core, refusals included. Files under 1 MiB are read on one core whatever you ask, so this tiny example only shows the same answer.

$ table --threads 4 --group status --agg count --format csv orders.csv
status,count
200,3
404,1
500,1

What it cannot do yet

  • Whole numbers only. A decimal in a number column is refused. Decimals, as exact numbers and never as floats, are on the backlog.
  • No row sort yet. You can sort the groups of a count or a sum, not the rows. A row sort is in progress.
  • No joins, and one input file at a time, named on the command line (no standard input).
  • No JSON lines, no Parquet. Only CSV and TSV (comma, tab or semicolon).
  • No guessing. Every column is text unless you say :int. There is no mean, no computed or renamed column, no or in a filter.

JSON lines, joins, mean, decimals and standard input are on the backlog, in rough order. Nothing there is promised.

How fast

A core is one of the independent workers inside a processor. By default table uses one; --threads 16 uses sixteen. DuckDB is a full database engine and a popular, fast way to query a CSV, so it is a fair yardstick. On these four questions one core of table is about as fast as, or faster than, DuckDB on all sixteen. With many distinct keys in a group-by, DuckDB on all cores wins.

Apple-silicon Mac with 16 cores. The file has five columns and a key with a few distinct values. Best of five runs, output thrown away, each tool’s answer checked against a Python answer first. csvtk 0.38.0 on one core (its filter is filter piped to grep); DuckDB 1.5.6. DuckDB’s 16-core times for filter and pick-2-columns are from an earlier run on the same machine. Miller is not installed on the Mac: on a different machine (Linux, 6 shared cores) Miller took 0.300 s to filter, 0.438 s to count and 0.649 s to sum, against table’s 0.074, 0.128 and 0.140 s there. All the tables, and how to rerun them.

Where it is slower

  • A group-by with a million distinct keys: 3.4 times slower than DuckDB on one core, and 9.4 times slower than DuckDB on all 16 (Mac). More cores do not help it.
  • Sorting rows: there is no row sort yet.
  • distinct over a column of unique values: 1.4 times slower than DuckDB on one core.

Memory: about 2 MB on the 32 MB file, and 1.6 to 1.8 MB on a 1 GB file, on one core (more cores use more: 36 to 50 MB with eight on the 1 GB file).

Try it

git clone https://github.com/alpibrusl/lex-sys
git clone https://github.com/alpibrusl/lexsys-table && cd lexsys-table
REV=$(sed -n 's/^lex-sys *= *"\([0-9a-f]*\)".*/\1/p' lex-sys.toml)
(cd ../lex-sys && git fetch -q origin && git checkout "$REV" && cargo build --release -p lex-sys)
export PATH=$PWD/../lex-sys/target/release:$PWD/build:$PATH
lex-sys build                       # builds build/table
table --select customer,bytes --format csv orders.csv    # with the file above saved as orders.csv

The compiler is the commit lex-sys.toml pins. You need Rust, clang and Python 3. table introspect lists every flag, rule and limit; table skill prints a short guide for an agent.

Built in lex-sys

lex-sys is a language whose compiler writes down what a program may do. For table that is the line below: it can read its arguments and the file, allocate memory, start threads and write to the terminal. It cannot use the network, call foreign code, read the clock or write a file. The compiler derived it, and CI fails if the binary says otherwise.

# manifests/table.authority.json
table    args, conc, dir_read, err_write, file_read, fs_read(""), heap, io_write
# bounded: true; foreign symbols: none; net_out, net_in, ffi, clock: absent

Status: early

  • What is listed above works and is tested. The list of what is missing is above too.
  • The speed numbers are for one file shape on two machines, plus a set of harder cases on the benchmarks page, where it loses some.
  • The program is built with one pinned compiler version, and that compiler is still changing.
